# bili-hardcore-jev

> 用 JEV（TypeSafe 的 System One 判断模型）自动完成 B 站「硬核会员试炼」的单文件 Python 脚本。
> 手机只用扫码登录一次，之后 100 道题全部在电脑上自动答完。

## 这是什么

B 站的硬核会员试炼只能在手机 APP 里点进去，但取题、交卷其实走的是一套接口。
本脚本在电脑上「扮成」B 站安卓版，直接跟服务器取题、交卷、查分：

```
取题 -> 交给 JEV 选答案 -> 自动提交 -> 循环 100 题 -> 出分
```

JEV 不是聊天大模型，它只做一件事：给定题目和几个选项，直接给出「选哪个 + 把握度多少」，
不写长篇大论。所以快，也便宜（100 题的调用成本可以忽略不计）。

## 使用前提

- B 站账号满 **6 级**（B 站硬性要求，脚本会自动检查）
- 每天只有 **3 次**挑战机会，跑一次消耗一次
- 硬核会员有效期 **365 天**，到期要重新试炼
- 需要一个 JEV 的 API key（TypeSafe 控制台申请）

## 准备

1. 把 key 存成一个文本文件，**第一行就是 key**。三选一告诉脚本：
   - 放到脚本同目录，文件名 `jev.txt`（推荐，已在 `.gitignore` 里，不会被上传）
   - 命令后面加 `--key-file 路径`
   - 设置环境变量 `JEV_KEY_FILE` 指向它
2. 先跑一次自检（不动 B 站账号，只发一次极小的 JEV 测试调用）：

   ```bash
   python bili_hardcore_jev.py --selftest
   ```

## 命令

| 命令 | 作用 |
| --- | --- |
| `python bili_hardcore_jev.py` | 完整流程：登录 -> 答题 -> 出分 |
| `python bili_hardcore_jev.py --selftest` | 自检：测 key、测二维码生成、测 JEV |
| `python bili_hardcore_jev.py --status` | 看登录状态、是不是硬核会员、今天剩几次 |
| `python bili_hardcore_jev.py --result` | 查分 |
| `python bili_hardcore_jev.py --logout` | 退出登录（删掉本机保存的登录凭证） |

## 跑起来是什么样

1. **第一次跑**：脚本生成二维码并弹出图片，用手机 B 站 APP「扫一扫」授权（约 60 秒有效），
   登录态保存 7 天。**手机只用做这一次扫码**。
2. 按回车确认开始（这一步才消耗今天 1 次机会）。
3. 选答题分区（1~3 个）→ 过一次图片验证码（脚本弹图，你照着输文字）。
   B 站的规矩是「交完验证码才算正式开局」，所以这一步过了才会真正开始。
4. 之后 100 题连续自动：每题打印一行（题号、JEV 选了哪个、把握度、累计答对多少）。
5. 答满 100 题或 B 站说答完，自动出总分和各分区得分，并再查一次硬核会员有没有生效。

**中途断了怎么办**：重跑脚本，它会发现上一局没答完，问你要不要接着答（不另扣次数）；
也可以选择放弃这一局重开。

## 已处理的坑

- **旧的答题记录**：B 站会把上一局残留的题目继续发回来（题号 > 100），提交就报 41103。
  脚本会把它当成「残留题」，走正常的开局流程，而不是傻傻地继续答。
- **B 站真实错误码**：41103 = 这题已经答过、41104 = 答得太快、41105 = 答题完成、
  41099 = 今天次数用完。脚本按真实含义分别处理（自动重试 / 等待 / 收尾）。
- **运行日志**：每一步的关键返回记在 `~/.bili-hardcore/run.log`，出问题发给别人看也方便。

## 风险提示（请先看这段）

- B 站的规则原文写明：**「若发现您在测试过程中使用非正常技术手段，您可能会被永久禁止参与挑战。」**
  本脚本属于自动化答题工具，用不用自己判断，后果自负。
- B 站的接口是逆向来的，B 站一改版脚本就可能失效，届时需要跟着修。
- 脚本只做「查等级 / 取题 / 交卷 / 查分」，不做别的事；登录凭证存在
  `~/.bili-hardcore/auth.json`（7 天后自动失效），**这个文件和你的 JEV key 都不要发给别人**。
- 每天只有 3 次机会，跑之前脚本会让你确认一次。
